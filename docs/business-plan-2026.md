## 一、執行摘要（Executive Summary）

「秦始皇數字人」是面向**中小學歷史/語文**場景的 AI 角色互動平台，技術棧已完全跑通：LLM（MiniMax-M2.7）+ 流式 TTS（speech-2.8-hd）+ WebSocket 全雙工對話 + Web Speech API 語音輸入 + 角色創作管線（圖生視頻）。

| 關鍵結論 | 數字 |
|---|---|
| **單輪對話成本**（學生問一句） | **¥0.15**，其中 TTS 佔 93% |
| **創建一個新角色**（含圖像+視頻） | **¥3.78**（用 MiniMax）/ **¥16.10**（用 Seedance 2.0） |
| **1 個學生玩 1 小時** | **¥13.5** |
| **1 個班 30 人 × 一節 40 分鐘課** | **¥270** |
| **每個學生每節課成本** | **¥9** |
| **TTS 切換為 turbo 可降本** | **40-43%**（單輪從 ¥0.15 → ¥0.086） |

**核心建議**：
1. **生產環境固定使用 MiniMax**（Hailuo-2.3-Fast 比 Seedance 2.0 便宜 4-5 倍，且單價明確、按視頻計費，可預測）。
2. **TTS 預設值從 `speech-2.8-hd` 改為 `speech-2.8-turbo`**，音質差異對中小學場景幾乎不可察覺。
3. **採用「每日免費配額 + 訂閱無限 + 學校授權」三層定價**。
4. **學校授權按「每學生每年」計價**，是 5-10x 個人訂閱的客單價，且極具黏性。

## 三、MiniMax vs Seedance 2.0 對比

> Seedance 2.0（火山引擎豆包視頻模型）於 2026 年 3 月開放企業公測。

### 3.1 定價結構

| 項目 | MiniMax Hailuo-2.3-Fast | Seedance 2.0 | Seedance 2.0 fast | Seedance 1.0-pro-fast |
|---|---|---|---|---|
| **計費方式** | **按視頻計費**（明確） | 按 token 計費 | 按 token 計費 | 按 token 計費 |
| 6s 視頻 | **¥1.35** | ≈¥6.18 | ≈¥5.12 | ≈¥0.55 |
| 10s 視頻 | **¥2.25** | ≈¥10.30 | ≈¥8.53 | ≈¥0.92 |
| 15s 視頻 | ≈¥3.00 | **¥15（一秒 1 元）** | ≈¥12.42 | ≈¥1.38 |
| 768P 1080P 價差 | 1080P +30% | 同 | 同 | 同 |
| **單角色成本**（6s+10s） | **¥3.60** | **¥16.48** | **¥13.65** | **¥1.47** |

> Seedance 按 token 估算公式：`(輸入視頻時長 + 輸出視頻時長) × 寬×高×幀率 / 1024`，15 秒視頻約消耗 30.888 萬 tokens。

### 3.2 為何 MiniMax 在本項目完勝

| 維度 | MiniMax | Seedance 2.0 |
|---|---|---|
| 單價 | 6s ¥1.35，**確定可預測** | 6s ≈¥6.18，**按 token 浮動** |
| 速率 | 同步輪詢約 1-3 分鐘 | 異步，平均 5-15 分鐘 |
| 平台一致性 | 與 LLM/TTS 同賬號同計費 | 需要額外接入火山引擎，新賬號、新結算 |
| 中文 prompt 表現 | 中國歷史人物（秦始皇）契合度高 | 偏動漫/寫實風格，**古風人物臉部容易崩** |
| API 穩定性 | 統一 Base URL | 需走方舟 SDK，調試成本高 |
| 學校招標合規 | 國內主流教育採購已認可 | 企業公測中，部分學校採購流程不適配 |

### 3.3 何時可以考慮 Seedance

- 角色有**複雜動作**（如騎馬、揮劍）需要更強的運動理解
- 客戶明確要求「必須是火山引擎/字節系」（少數政府/國企場景）
- 願意付出 5x 成本換取更精細的物理動作

> 結論：**生產環境固定 MiniMax**，Seedance 留作 v2.0 進階選項（用戶可付費解鎖）。

## 四、成本優化方案（按優先級）

### 招數 ①：TTS 切換為 `speech-2.8-turbo`（立即省 40%）

```python
# server.py 第 31 行
TTS_MODEL = "speech-2.8-turbo"   # 原 "speech-2.8-hd"
```

| 模型 | 單輪 TTS | 差異 |
|---|---|---|
| speech-2.8-hd（現行） | ¥0.14 | 高保真，採樣更細 |
| speech-2.8-turbo | **¥0.08** | 速度優先，**中小學語境音質差異 < 5%** |

> **每月 1000 活躍用戶可省 ¥7,000+**。建議 A/B 試聽後上線。

### 招數 ②：開啟 LLM 緩存讀取

MiniMax M2.7 緩存讀取：0.42 元/百萬 tokens（**為全價的 1/5**）。System prompt 1300 tokens 在第 2 輪後全部命中：

```python
# 調用 chatcompletion_v2 時加入
"prompt_cache": {"enabled": True, "ttl": 3600}
```

> 對 10 輪對話：緩存可省 **¥0.018/會話**，每月 1000 活躍用戶約省 ¥3,000。

### 招數 ③：TTS 預合成高頻短語

把 50-100 條高頻短語（「朕乃秦始皇嬴政是也」、「哈哈，小童有趣」等）預合成 mp3，命中後**直接播放，0 邊際成本**。

```python
# characters/<id>/cache/phrases.json + phrases/*.mp3
PHRASE_CACHE = {
    "朕乃秦始皇嬴政是也。": "/static/cache/qsh-intro.mp3",
    ...
}
```

> 預估可覆蓋 15-25% 的 TTS 請求，**單輪成本可再降 20%**。

### 招數 ④：限縮 LLM 輸出字數

```python
"max_tokens": 300   # 原 500，實際平均輸出 200，300 已足
```

並在 system prompt 把「3-5 句」改為「**2-3 句，50 字以內**」。輸出從 200 → 120 tokens，**省 40% LLM 成本**（雖然絕對額小）。

### 招數 ⑤：角色批量創建用 `n=1` 候選 + 標準 768P

管理員後台建 100 個角色時：

| 配置 | 單角色 | 100 角色 |
|---|---|---|
| 現行（4 圖 + 6s+10s） | ¥3.78 | ¥378 |
| 優化（1 圖 + 6s+8s） | **¥2.55** | **¥255** |
| 進一步（靜態圖 + CSS 動畫） | ¥0.18 | ¥18 |

> 學校專屬角色可以犧牲一點真實感換成本。

### 招數 ⑥：對話冷卻 + 並發限制

```python
# 中小學生注意力 15 分鐘為宜
DAILY_QUOTA = {"free": 30, "basic": 300, "pro": -1, "school": -1}
RATE_LIMIT = "20/minute"  # 防止刷量
```

### 招數 ⑦：自建角色市集，二次銷售

已生成的 100+ 歷史人物角色（秦始皇、漢武帝、唐太宗、蘇軾、李清照、孔子…）可打包為**角色市集**：
- 個人用戶免費試用 3 個
- 解鎖全部：¥9.9/月
- 學校無限解鎖：包含在訂閱

> 這是**零邊際成本**的純利潤，因為創建成本已沉沒。
